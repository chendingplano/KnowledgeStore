# Overview [[def:Onyx, agentic system]]

**Onyx is a self-hostable, open-source “ChatGPT for your company” that connects LLMs with your internal data, tools, and workflows.** ([GitHub][1])


```
[LLMs (OpenAI, local, etc.)]
           ↑
     Onyx Platform
           ↑
[Your data: docs, Slack, GitHub, DBs, etc.]
```

It’s NOT just a UI — it’s:

* Chat interface
* RAG system
* Agent framework
* Data ingestion + connectors
* Orchestration layer

---

# Core architecture

### 1. LLM-agnostic layer

* Works with **any LLM** (OpenAI, local models, etc.) ([GitHub][1])
* You can swap models without changing the system

---

### 2. Knowledge layer (RAG + graph)

* Hybrid search (vector + keyword + graph)
* Connects to **40+ data sources** (Drive, Slack, GitHub…) ([GitHub][1])
* Builds a **knowledge graph + contextual retrieval**

**Comment**: 40+ data sources are important. We can use them to connect to these data sources.

---

### 3. Agent layer

* Create **custom agents**:

  * Instructions (prompt)
  * Knowledge scope
  * Actions/tools
    ([GitHub][1])

Very similar to “skills” or “sub-agents” concepts.

---

### 4. Tooling / actions layer

* Web search
* Code interpreter
* External app actions
  ([Onyx Documentation][2])

👉 This is basically:

> MCP + tool-use runtime

---

### 5. Interface layer

* Chat UI (ChatGPT-like)
* Multi-user collaboration
* Chat history + sharing

---

# 🔥 Key features (what makes it interesting)

## 1. Fully self-hostable (big deal)

* Runs locally / on-prem / cloud
* Can be **air-gapped** ([GitHub][1])

👉 Strong alignment with:

* your **sandbox / containment** thinking
* enterprise privacy concerns

---

## 2. “Chat over your company”

Instead of:

> LLM knows general knowledge

You get:

> LLM + your company’s knowledge

* Docs
* Conversations
* Code
* CRM data

👉 This is basically:
**Enterprise RAG done right**

---

## 3. Built-in “deep research”

* Multi-step agentic search across:

  * web
  * internal data
    ([GitHub][1])

👉 Comparable to:

* OpenAI Deep Research
* but grounded in your data

---

## 4. Connectors ecosystem

* 40+ integrations
* Sync + access control respected

👉 Important detail:

* It preserves **permissions**
* Not just raw ingestion

---

## 5. Modular + extensible

* Open-source (mostly MIT) ([Reddit][3])
* Designed to be customized

---

## 6. Auto Execute Code

Onyx can execute the Python code generated by Onyx dynamically, such as use Python to analyze data, etc.

# ⚖️ Strengths vs limitations

## ✅ Strengths

* Production-ready (auth, roles, UI, etc.) ([Medium][4])
* Strong RAG + connectors
* Self-hosted → control + privacy
* LLM-agnostic
* Integrated agent system

---

## ⚠️ Limitations (important for you)

1. **Not path-native **

   * Data is connector/index-driven
   * Not filesystem exploration-first

2. **Still “chat-centric”**

   * UI-driven, not CLI/tool-first
   * Less natural for agents exploring data

3. **Opinionated architecture**

   * Harder to deeply customize retrieval internals vs building your own MKBP backend

4. **Agent autonomy is limited**

   * More “interactive agent” than “always-on system”
