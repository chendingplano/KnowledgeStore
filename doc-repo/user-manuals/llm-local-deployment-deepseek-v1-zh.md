# DeepSeek-Flash 本地部署用户手册

**适用模型版本**：DeepSeek-V4.1-Flash-1017（API 模型名 `deepseek-flash`）  
**文档性质**：基于公开社区资料与官方 vLLM recipe 整理，非 DeepSeek 官方手册  
**重要提示**：截至 2026 年 11 月，DeepSeek V4.1 Flash 完整权重约 **511 GB**，单机部署显存底线为 **614 GB**。**绝大多数个人开发者与中小团队无法在本地运行满血版本**，应优先考虑 API 调用或社区量化版本。


## 1. 量化选项与影响

DeepSeek V4.1 Flash 的权重发布形态与常规模型有本质区别：**官方发布的权重已经是原生混合量化**，而非 FP16/BF16 全精度。理解这一点是选择部署方案的前提。

### 1.1 官方原生量化（FP8 + FP4）

官方 HuggingFace 仓库中的 48 个 safetensors 分片即为 FP8 密集权重加 FP4 专家权重的组合。这意味着：

- **不需要也不建议**再做 GPTQ/AWQ 等二次量化，二次量化可能破坏原生量化的兼容性；
- 磁盘占用约 **511 GB**，其中 196B 参数的 Engram 记忆表约占 189 GiB；
- Engram 表**无法跳过**：每个 token 推理时都会访问该表，必须常驻显存。

### 1.2 社区量化版本（3-bit 及以下）

由于官方权重对硬件要求极高，社区出现了第三方量化包，主要面向消费级/工作站硬件：

| 量化方案 | 代表来源 | 磁盘/内存占用 | 质量影响 | 适用场景 |
|---------|---------|-------------|---------|----------|
| EXL3 3-bit | Diffbot 打包，GitHub 社区使用 | 显著低于官方 FP8/FP4 | 存在精度损失，社区称“合理质量” | 双 RTX PRO 6000 等工作站 |
| 2-bit（约 167 GB） | 社区指南提及 | 约 167 GB | 损失较大，适合验证/实验 | Mac Studio 256GB 等 |
| IQ2 级别 | DGX Spark 社区实测 | 可装入 128GB 统一内存 | 损失明显，仅作演示/轻量使用 | DGX Spark 单机 |

**关键结论**：社区量化是个人用户本地运行的唯一现实路径，但会牺牲模型质量。官方原生权重面向的是 8 卡 H200 级别的生产环境。


## 2 硬件要求

### 2.1 官方满血版（FP8/FP4 原生权重）最低要求

根据 vLLM 官方 recipe：

- **显存底线**：**614 GB**（511 GB 权重 × 1.2 倍余量）；
- **已验证单机平台**：8 卡 H200 节点，或 GB200 NVL4 托盘；
- **系统内存**：需额外容纳加载缓冲与引擎开销，建议 ≥ 256 GB；
- **存储**：约 511 GB 权重文件，建议 NVMe SSD，首次加载时间以小时计；
- **上下文注意**：模型虽支持 1M token，但 vLLM recipe 明确提醒“1M context will need the context or batch capped”，即便 H200 节点也需限制上下文或并发。

### 2.2 社区量化版硬件门槛

| 量化级别 | 显存/内存需求 | 典型硬件 |
|---------|-------------|----------|
| EXL3 3-bit | 双卡约 96GB+ 显存 | 2× RTX PRO 6000 Blackwell（96GB/卡），系统 RAM 建议 128 GB+ |
| 2-bit | 统一内存约 167 GB+ | Mac Studio 256GB / 512GB |
| IQ2 | 约 128 GB 统一内存 | DGX Spark 128GB |


## 3 推荐硬件配置与 Tokens/s 估算

> **说明**：以下数据来自社区实测或公开报告，非官方基准。不同框架、批处理大小、上下文长度均会影响实际吞吐。tokens/s 指**单流解码速度**（非批处理总吞吐），单位为 token/秒。

### 3.1 配置一：生产级满血部署（8× H200）

| 项目 | 规格 |
|------|------|
| GPU | 8× NVIDIA H200（141GB HBM3e） |
| 总显存 | 1128 GB |
| 系统内存 | 512 GB+ |
| 存储 | 4TB+ NVMe SSD |
| 推理框架 | vLLM / SGLang 专用预览镜像 |
| **预估 Tokens/s** | **官方未公布公开基准；社区无可靠单流数据** |

**适用对象**：有私有化刚需的企业、MLOps 团队。部署成本五位数美元级别，个人不可行。vLLM 和 SGLang 在发布初期仅提供专用预览镜像，非正式 pip 包。

### 3.2 配置二：工作站量化部署（2× RTX PRO 6000 Blackwell + EXL3 3-bit）

| 项目 | 规格 |
|------|------|
| GPU | 2× NVIDIA RTX PRO 6000 Blackwell（96GB 显存/卡） |
| 系统内存 | 128 GB 推荐（最低约 96–112 GiB） |
| 存储 | NVMe SSD（用于 Engram 表 NVMe offload） |
| 量化 | Diffbot EXL3 3-bit |
| 推理框架 | vLLM（定制配置） |
| 上下文 | 最高 512K（实测配置，6 并发） |
| **实测 Prefill 速度** | 约 **10k tok/s**（经 32 线程 gather 优化后，原为 1–1.4k） |
| **预估 Decode 速度** | **社区未公布精确单流 decode 数值**；该配置侧重多并发长上下文场景（6 路 512K） |

该配置来自 GitHub 社区项目，核心优化包括：Engram 表从 NVMe 按需读取（而非常驻内存）、LMCache 分层缓存、CPU host-experts 仅用于 decode 阶段（提升 12–17%）。这是一套面向“可用的长上下文 agent 工作流”的工程方案，而非追求极限单流速度。

### 3.3 配置三：轻量/实验级（DGX Spark 双机 或 Mac Studio 256GB）

| 项目 | DGX Spark 双机方案 | Mac Studio 256GB 方案 |
|------|-------------------|---------------------|
| 硬件 | 2× NVIDIA DGX Spark（各 128GB 统一内存） | Mac Studio M3 Ultra 256GB |
| 量化 | IQ2 级别 | MLX 2-bit |
| 推理框架 | 社区定制（基于 llama.cpp/vLLM 变体） | MLX |
| **实测 Tokens/s** | **约 6–7 tok/s**（V4-Flash IQ2） | **约 9.5 tok/s**（V4.1-Flash MLX 2-bit） |
| 另一社区报告 | **60–70 tok/s 单流**（两台 DGX Spark，V4-Flash 0731，配置细节未完全公开） | — |

**注意 1**：DGX Spark 的 6–7 tok/s 与 60–70 tok/s 两个数据差距极大，前者来自量化指南汇总，后者来自 V2EX 用户分享。差距可能源于量化级别不同（IQ2 vs 其他）、框架优化差异、或上下文/批处理设置不同。**建议将 6–7 tok/s 视为保守预期**。Mac Studio 的 9.5 tok/s 是一份社区实测数据，可作为参考上限。

**注意 2**：这个方案可用作测试系统，但不建议用于生产系统，无论从输出速度、还是大模型的输出质量都很难达到可用的水平。

## 4. 部署路线选择建议

| 你的情况 | 推荐路线 | 指导性建议 |
|---------|----------|---------|
| 有 8 卡 H200 或 GB200 NVL4 | vLLM / SGLang 官方镜像，走满血部署 | 推荐 |
| 有双 RTX PRO 6000 等工作站卡 | EXL3 3-bit + vLLM 定制配置，参考 GitHub 社区方案 | 不得已情况下使用，使用前多测试其性能和质量 |
| 有 DGX Spark / Mac Studio 大内存设备 | 2-bit/IQ2 量化 + 对应框架，预期 6–10 tok/s | 仅限于测试系统 |
| 只有消费级显卡（24GB 及以下）或笔记本 | **不建议本地部署**，使用 DeepSeek API | 不建议 |
| 需要生产级稳定性但无自建条件 | DeepSeek 官方 API（deepseek-flash，并发上限 2500） | 建议 |


## 5 重要注意事项

1. **框架成熟度**：截至 V4.1 Flash 发布初期，vLLM 和 SGLang 仅提供专用预览镜像，llama.cpp 尚未合入 V4.1 架构支持，Ollama 不兼容。部署前务必确认框架版本是否支持 `deepseek_v41` 架构。

2. **Engram 表是显存关键**：196B 参数的 Engram 记忆表约 189 GiB，必须可被推理引擎访问。社区方案通过 NVMe 按需读取来降低内存占用，但会增加实现复杂度。

3. **1M 上下文不等于满配可用**：即使硬件满足显存底线，vLLM recipe 也明确要求对上下文或批处理做限制。实际部署时应从较小上下文（如 128K 或 256K）开始测试。

4. **量化质量不可逆**：社区 2-bit/3-bit 量化会带来可感知的精度下降。如果应用场景对准确性要求高（如代码生成、数学推理），应优先考虑 API 而非本地量化版。

5. **本手册基于 2026 年 11 月前的公开信息**。DeepSeek 模型迭代迅速，框架支持情况可能变化，部署前请查阅 vLLM/SGLang 最新 release notes 及 HuggingFace 模型卡。
