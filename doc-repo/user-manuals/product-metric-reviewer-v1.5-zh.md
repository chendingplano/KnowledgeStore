# 产品评审（Product Review）

菜单路径：**Development → Applications → Product Review**

## 1. 功能简介

Product Review 回答一个问题：*哪些指标适用于这个产品？* 你输入一个产品名称，它会返回知识库中所有适用于该产品的指标。每条结果都附带其来源文档、确切的行号，以及一段通俗的纳入理由。

它的查找能力比按名称搜索更强。一个产品由模块和部件组成，而大多数指标归属于某个部件，而不是产品整体：*显示亮度*属于显示屏，*电池续航*属于电池。此外，它还覆盖产品在其整个生命周期中必须满足的条件，例如存储温度或跌落测试，这类指标的主体是一个条件，而不是某个部件。这些指标都不会提及产品名称。Product Review 会先构建该产品的全貌（其部件和生命周期条件），然后找出与全貌中任一环节相关联的所有指标，无论它们位于知识库的哪个位置。

你可以用它来整理标准符合性文件，检查产品的文档是否覆盖了所需的测量项，或查看产品的哪些部分缺少支撑性指标。

## 2. 开始之前

- 你需要拥有 ChenWeb 登录账号，并有权访问 **Applications → Product Review**。如果菜单中没有该项，请咨询管理员确认你的角色。（其他 Applications 菜单项，如 Installed、Browse、Configure 和 Generate Doc，仅限管理员使用；Product Review 不受此限制。）
- 本手册中的所有操作都在页面本身完成，无需运维人员介入。
- 开始评审后，结果会在同一页面中打开。通过菜单离开 Product Review 后再返回，总是会回到起始屏幕。

## 3. 你会看到的概念

**范围档案（Scope profile）。** 针对单个产品保存的、可复用的描述：包括产品本身、按拆解深度逐层嵌套的部件，以及一组固定的生命周期 **方面（aspects）**（存储、运输、维护、使用环境、安全等）。一份档案可服务于多次运行。

**档案如何构建。** 在你看到范围树之前，系统会自动完成以下步骤：

1. 一个 AI 步骤根据产品名称和描述提出拆解方案。
2. 每个部件都会被 *锚定（grounded）*：在可能的情况下，与知识库跨文档已追踪的某个标识相匹配。无法匹配的部件仍保留在树中，并按文本进行匹配。
3. 利用知识库中已记录的部件关系对树进行 *扩展（expanded）*，这可能会补充 AI 步骤未曾提及的真实部件。

**层级（Tiers）。** 每条指标恰好带有一个层级，取决于它匹配到的对象：

| 层级 | 含义 |
|---|---|
| `direct` | 指标的主体就是产品本身。 |
| `part` | 主体是该产品的某个部件或模块。 |
| `aspect` | 主体或语境是某个生命周期方面（存储、安全等）。 |
| `document_scope` | 未匹配到具体部件，但在一份与该产品相关的文档中找到。 |

**两种发现指标的方式。** 按文档（关于该产品的文档中的每一条指标）和按主体（主体与某个部件匹配的每一条指标，无论位于哪份文档中）。两者会被合并。无论通过哪种方式或两种方式都找到的指标，只会出现一次，并记录其发现方式。在界面上，路径显示为 `document_first` 或 `direct`。

**运行与报告。** 每次执行都是一次 *运行（run）*，包含一份结果列表和一份覆盖报告。运行可重复执行并会被保留；每次运行都会记住其所使用的档案版本。

**档案版本。** 编辑拆解结构会提升版本号。编辑操作永远不会改变过去运行的结果。

## 4. 开始评审

打开 **Applications → Product Review**。顶部的卡片 **Review a product** 包含以下字段：

| 字段 | 说明 |
|---|---|
| **Product name**（必填） | 输入时会从产品名称目录中给出建议。匹配中文名称、英文名称和别名（最多 20 条建议）。选中某个建议后，会以其英文名称记录在评审中。如果目录中没有该名称，也可以直接输入。 |
| **Keywords**（可选） | 以逗号分隔。存储于产品上，可用于筛选 Past reviews。 |
| **Image Generation Model** | 用于绘制产品示意图的模型（见下文）。列表来自部署配置；第一项为默认值。 |
| **Short description**（可选） | 关于产品的一两句话描述。有助于拆解。 |
| **Notes**（可选） | 供日后阅读该次运行的人员参考的背景信息。 |

点击 **Start**。页面会创建档案、构建档案、运行首次评审，并打开结果。

**自动绘制示意图。** 点击 Start 时，页面会查找同名的现有产品示意图并将其关联。如果不存在，则使用你所选的模型生成一张。若绘制失败，评审仍会继续，只是没有配图。你之后可以在结果页面中生成示意图。

### 如果该产品已经被评审过

如果名称与某个现有档案完全匹配（忽略大小写和首尾空格），系统不会创建第二份档案。你会看到一张 **Already reviewed** 卡片，其中包括：

- **View results**：打开最近一次已完成的运行。
- **Re-run**：针对现有档案启动一次新的运行。
- **Start over**：关闭该卡片，返回表单。

如果档案从未完成过运行，则只提供 **Re-run**。"Ventilator" 与 "Ventilator Model X" 是不同的产品。

### Past reviews

表单下方的 **Past reviews** 为每份档案显示一张卡片。每张卡片包含：

- 产品示意图（或占位图）；
- 名称，两者都存在时显示为 `中文 / English`；
- 关键词、描述，以及最近一次运行的指标数量；
- 最近一次运行的状态（Completed、Running…、Failed、Pending、Never run），以及对于已完成的运行，距其完成已过去多久；
- 当档案有运行记录时显示的 **View results** 按钮。

**选中卡片**（除 View results 按钮外的任意位置）会将该产品的名称、描述、关键词和备注填入表单，并将按钮从 **Start** 改为 **Re-Run**。**Re-Run** 会基于已保存的档案启动新的运行；若档案从未运行过，则开始首次运行；运行完成后打开结果。如果你将产品名称改为其他内容，选中状态会被取消，按钮恢复为 **Start**。

卡片上方的控件：

- **Sort**：按时间、产品名称或指标数量排序，升序或降序。
- **Filter by keywords**：勾选一个或多个关键词。产品只要带有任一被勾选的关键词即可匹配。被勾选的关键词以标签（chip）形式显示；点击标签即可移除。
- **Filter by name**：不区分大小写的"包含"搜索。

你更改这些设置时，列表会随之更新。列表没有分页，且只显示有限数量的档案，因此非常旧的评审可能不会显示。不过，你仍可在表单中输入其完整名称找到它。

## 5. 结果页面

开始或打开一次运行后，会显示评审结果。**← Back** 返回起始屏幕。

**页眉。** 显示产品名称和一行摘要：运行状态、匹配到某个部件的结果数、来自文档范围的结果数，以及范围内的文档数。如果有结果因大小上限被丢弃，会显示警告及数量。右侧有两个按钮：

- **Export CSV** 下载本次运行的全部结果。列包括：`artifact_type`、`artifact_id`、`primary_label`、`document_record_id`、`source_line_spans`、`matched_node_id`、`tier`、`score`、`paths`、`inclusion_reason`。
- **Re-run**：参见[第 9 节](#9-重新运行审查)。

如果在本次运行之后修改了档案，横幅会说明该运行使用的版本、当前版本，并提供 **Re-run** 按钮。

**标签页。** **Results**（附结果数量）和 **Report**（附缺口数量）。

### 5.1 产品示意图

Results 标签页顶部是产品的分解视图风格插图。它仅作为辅助理解的示意，并非工程模型，也没有可下载的文件。

如果档案尚无示意图，则会显示生成器。它包含 **Drawing prompt**（根据产品名称及其部件预先填写，可编辑）和 **Model** 下拉菜单。点击 **Generate 3D Drawing**，查看结果，然后点击 **Keep** 保存（保存至产品，之后会自动显示），或点击 **Discard** 放弃并重试。保存示意图后，**Regenerate** 可将其替换。在新图被保存之前，当前示意图会一直可见。每个产品只保存一张示意图。

### 5.2 布局

示意图下方从左到右分为三个区域：

1. **范围树**（[第 6 节](#6-范围树)）。
2. **结果列表**（[第 7 节](#7-结果列表)）。
3. **右侧面板**：左侧为 **源 PDF**，右侧为 **Metric Details** 面板（[第 8 节](#8-证据指标详情与源-pdf)）。

拖动任意细分隔线即可调整大小：区域之间、PDF 与 Metric Details 之间，以及示意图下方（调整其高度）。范围树的标题栏有一个折叠按钮（面板图标），可将其缩小为窄条；再次点击即可展开。Results 标签页使用整个窗口宽度。你的尺寸设置和折叠状态会按浏览器记忆，而非按账户记忆；Report 标签页有自己的布局。在窄窗口中，各面板会上下堆叠。

本页面会隐藏通用的 "App Status" 侧边面板，因为 Product Review 会使用该空间显示自己的面板。

## 6. 范围树

范围树的根节点是产品，其模块和部件位于其下，生命周期方面也在其中。每一行显示：

- **类型标记（kind badge）**：product、module、part 或 aspect；
- **来源标记（origin marker）**：`llm`（由 AI 步骤提出）、`graph`（由知识库关系添加）或 `user`（由人工添加）；
- **锚定指示点（grounding dot）**：与知识库中的某个标识关联，或仅为文本；
- **警告三角形**：当匹配的标识存在歧义、需要人工判断时显示；
- **计数**：本次运行中归属于该节点的结果数。

点击某一行，可将结果列表过滤为该节点。再次点击，或使用 **Clear**，即可取消过滤。有子节点的行可以折叠。

行操作：

- **✓ Accept** / **✕ Reject**：在未来的运行中纳入或排除该节点。被拒绝的节点会以删除线显示。
- **铅笔图标**：重命名节点。按 Enter 或点击 **Save**。
- **+**：在该节点下添加 **part** 或 **module**，用于补充拆解中遗漏的内容。
- **垃圾桶图标**：删除节点。产品根节点不能被删除。

每次编辑都会提升档案版本。**屏幕上的运行保留其自身的结果。** 只有新的运行才会采用你的编辑，因此编辑后请使用 **Re-run**。

## 7. 结果列表

结果按其匹配的范围树节点分组，分组中结果最多的排在最前。每行显示层级、指标名称、文档编号（`#123`）、路径和分数。

结果列表上方的筛选器，可与所选的树节点组合使用：

- **Tier**：`direct`、`part`、`aspect` 或 `document_scope`。
- **Path**：`direct`（按主体找到）或 `document_first`（通过文档找到）。
- **Document**：某一份来源文档，显示为 `#id · kind`。
- **Text**：对名称、纳入理由和指标 ID 进行的自由文本搜索。

没有具体部件匹配的结果（`document_scope`）会被折叠到一个 **Document scope** 分组中，只显示数量，因为一份大型标准可能贡献数百条结果。点击分组标题即可展开。

如果没有任何结果匹配，面板会予以说明。如果运行存在缺口，面板会链接到这些缺口。

## 8. 证据、指标详情与源 PDF

点击某一结果行，会发生两件事：

- **源 PDF** 会在右侧面板中打开到第一个被引用的页面，并高亮显示被引用的行。如果该文档没有 PDF 预览，面板会予以说明。
- **Metric Details** 随之填充：

| 字段 | 含义 |
|---|---|
| Artifact | 指标的 ID。 |
| Metric name、Subject | 来自指标记录。 |
| Object | 范围树节点的规范对象（或 "None (document scope)"）。 |
| Document | `#id`。点击可打开对话框，查看文档的记录字段和文档元数据。 |
| Matched name | 该结果所匹配的范围树节点。 |
| Path | 发现方式。 |
| Value、Threshold、Unit、Frequency、Class、Data type、Range type | 来自指标记录；为空时显示 `—`。 |
| Score | 排序分数。 |
| Line spans | 源文本行。 |
| Inclusion reason | 用通俗语言解释该结果为何被纳入。 |

**Full Details**（位于 Metric Details 底部的按钮）会打开一个对话框，显示完整的指标记录，与 Knowledge Base → Metrics 工作区中的显示一致。它分为五组：**Metric**、**Metadata**、**Context**、**Grounding** 和 **Reasoning**。每个组标题会显示已填写字段的数量，例如 `(7/12)`。可通过 **Close**、按 Escape 键或点击对话框外部关闭它。你会停留在当前页面。

在依赖任何结果之前，请务必对照高亮的源文本进行核实。

## 9. 重新运行审查

选择 **Re-run**（位于页眉，或陈旧版本横幅中），即可对同一评审执行一次新的运行。在知识库中新增文档之后，或在整理范围树之后，请执行此操作。新运行会获得自己的编号、结果和报告，报告会将其与上一次运行进行比较。早期的运行不会被更改或删除。

## 10. 报告标签页

- **汇总计数**：已归属（匹配到某个部件）、文档范围、范围内文档数，以及被截断（因上限被丢弃）的数量。
- **按范围节点的覆盖情况**：每个已接受的节点一行，显示其类型、锚定状态，以及匹配到的指标数和文档数。指标数为零的行会被高亮显示。
- **覆盖缺口**：每个已接受但匹配到零条指标的节点。这往往是最有用的部分。"未找到加湿器模块的指标"是一项发现，而不是空白。锚定为纯文本的缺口，更可能是系统无法准确定位该部件，而非文档中真正存在的空白。整理该节点可能会在下次运行时消除该缺口。
- **截断**：结果被上限截断的文档，以及被丢弃的数量。
- **自第 N 次运行以来的变化**（非首次运行时显示）：结果的 **Added**（新增）、**Removed**（移除）和 **Re-tiered**（层级变更）。如果两次运行之间档案版本发生了变化，报告会予以说明，以便你区分是文档的变化，还是你对拆解结构所做的修改。

## 11. 理解结果

- **没有结果。** 查看缺口列表。可能需要为档案补充更多或锚定更准确的节点，也可能是知识库确实缺乏相应覆盖。
- **结果需要人工判断。** Product Review 是一个辅助检索工具，而非合规决策工具。返回的指标是系统认为相关的指标，但并不保证其正确、现行或具有约束力。
- **同一版本下可重复。** AI 模型仅用于初始拆解（以及偶尔将不常见的生命周期方面映射到标准类别）和示意图绘制。检索、评分、分层和报告均为确定性过程。相同的档案版本和文档将得到相同的结果。

## 12. 当前限制

- 每份档案只对应一个产品。相关产品需要单独建立档案。
- 仅包含指标。条款（provisions）、库存项目及类似内容不包括在内。
- 每份文档和每次运行都有数量上限。达到上限时，保留得分最高的结果，并记录被丢弃的数量；部件匹配的结果永远不会为了给文档范围的结果腾出位置而被丢弃。
- 生命周期方面列表来自部署配置，不同安装环境可能有所不同。
- AI 拆解和图谱扩展并不详尽。请使用节点整理功能来修补缺口。
- 重复检测仅按完全相同的名称匹配。
- Past reviews 没有分页，且数量有上限。
- 从选中的卡片点击 Re-Run 时，不会保存你编辑过的描述或关键词。只有编辑过的备注会带入新的运行。
- 示意图为二维插图，每份档案一张；除非你启动评审（自动绘制）或主动选择生成，否则不会生成。
- 面板尺寸按浏览器记忆。
- 产品名称建议来自每次访问页面时加载一次的目录。之后添加到目录中的名称，需要重新加载页面才会出现。

## 13. 操作指南

以下是常见任务的简要步骤。每一步都使用屏幕上显示的控件名称。

### 13.1 如何评审一个新产品

1. 打开 **Development → Applications → Product Review**。
2. 输入产品名称。如有合适的建议，选择它。
3. 可选：添加关键词、描述和备注，并选择 **Image Generation Model**。
4. 点击 **Start**，等待结果页面打开。

### 13.2 如何无需重新运行即可重新打开过去的评审

1. 在起始屏幕的 **Past reviews** 中找到该产品。如果列表较长，可使用 **Filter by name** 或 **Filter by keywords**。
2. 点击其卡片上的 **View results**。

### 13.3 如何重新运行过去的评审

1. 选中该产品的卡片。表单会自动填充，按钮变为 **Re-Run**。
2. 可选：编辑备注。只有备注会带入新的运行。
3. 点击 **Re-Run**。

### 13.4 如何找回从 Past reviews 中消失的产品

在 **Product name** 中输入其完整名称，然后点击 **Start**。你会看到 **Already reviewed** 卡片。选择 **View results** 或 **Re-run**。不会创建重复的档案。

### 13.5 如何快速找到最相关的指标

1. 在 Results 标签页中，将 **Tier** 设为 `direct` 或 `part`。这些是与产品或其某个部件直接相关的指标。
2. 保持 **Document scope** 分组折叠。
3. 利用每行显示的分数，决定优先查看哪一条。

### 13.6 如何只评审产品的某一个部件

1. 在范围树中点击该部件所在的行。结果列表将只显示该节点。
2. 再次点击该行，或点击 **Clear**，即可查看全部结果。

### 13.7 如何核实某条指标的来源

1. 点击该结果行。
2. 阅读 PDF 面板中高亮的行。如有需要，可在查看器中缩放或切换页面。
3. 阅读 Metric Details 中的 **Inclusion reason**。
4. 点击 **Document** 编号可查看文档的记录和元数据，或点击 **Full Details** 查看完整的指标记录。

### 13.8 如何只查看某一份文档中的指标

将结果列表上方的 **Document** 设置为目标文档，例如 `#123 · standard`。

### 13.9 如何纠正错误或缺失的部件，并查看效果

1. 在范围树中使用行操作：点击 **✕** 拒绝错误的节点，点击铅笔图标进行重命名，点击 **+** 添加缺失的部件或模块，或点击垃圾桶图标删除节点。
2. 点击页眉中的 **Re-run**。在你这样做之前，屏幕上的结果不会改变。
3. 打开 Report 标签页，阅读 **自第 N 次运行以来的变化**，查看你的编辑新增或移除了哪些内容。

### 13.10 如何查找某个产品缺失的内容

1. 打开 **Report** 标签页。
2. 阅读 **Coverage gaps**。每一项都是一个已接受但没有指标的节点。
3. 对于锚定为纯文本的缺口，请整理该节点（将其重命名为文档中使用的术语），然后点击 **Re-run**。

### 13.11 如何比较两次运行

重新运行评审，然后打开较新运行的 Report 标签页。**自第 N 次运行以来的变化** 会列出新增、移除和层级变更的结果。如果它提示档案版本已发生变化，则部分差异来自你的编辑。

### 13.12 如何导出结果

点击结果页眉中的 **Export CSV**。文件包含该次运行的全部结果，与屏幕上设置的筛选条件无关。

### 13.13 如何添加或替换产品示意图

1. 在 Results 标签页中，如有需要请编辑 **Drawing prompt**，并选择 **Model**。
2. 点击 **Generate 3D Drawing**，然后点击 **Keep** 保存或 **Discard** 放弃并重试。
3. 如需之后替换已保存的示意图，请点击 **Regenerate** 并重复上述步骤。

### 13.14 如何为结果腾出更多空间

点击范围树标题栏中的面板图标将其折叠，拖动分隔线，或拖动示意图下方的分隔线以缩短示意图。你的布局会在此浏览器中被记住。

### 13.15 如何为相关产品启动评审

输入新产品自身的名称，然后点击 **Start**。每个产品都有自己的档案。一个高度相关的产品是一次独立的评审，而不是现有评审的变体。

## 14. 故障排查

| 问题 | 检查事项 |
|---|---|
| Product Review 不在菜单中 | 在 **Development → Applications** 下查找。如果没有，请咨询管理员确认你的角色。 |
| 我看到的是 "Already reviewed" 而不是新的评审 | 已存在同名的档案。选择 **View results** 或 **Re-run**。 |
| 我很久以前做过的评审不在 Past reviews 中 | 列表有数量上限。请在表单中输入其完整名称。 |
| 我误选了某个过去的评审 | 更改 Product name 字段。选中状态会被取消，按钮恢复为 **Start**。 |
| 我对描述或关键词的编辑没有影响 Re-Run | 符合预期。只有备注会被带入。 |
| 点击 Start 后没有出现示意图 | 示意图为尽力而为。打开 Results 标签页，使用 **Generate 3D Drawing**。 |
| Report 标签页没有示意图区域 | 示意图只显示在 Results 标签页中。 |
| 示意图看起来不对 | 点击 **Discard**，修改提示词，然后重新生成。在点击 **Keep** 之前，不会保存任何内容。 |
| 结果列表看起来是空的 | 检查 Tier、Path、Document 和 Text 筛选器以及所选的树节点。展开折叠的 **Document scope** 分组。 |
| 我对树的编辑没有改变结果 | 符合预期。屏幕上的运行是固定的。请使用 **Re-run**。 |
| 横幅提示档案自本次运行以来已变化 | 点击 **Re-run**。 |
| 某个部件带有警告三角形 | 其匹配的标识在知识库中存在歧义，需要人工判断。 |
| 某个节点的结果为零 | 检查报告中的缺口列表以及该节点的锚定情况（第 10 节）。 |
| PDF 面板为空 | 点击结果行。如果面板提示没有可用的预览，说明该文档没有 PDF。 |
| 面板太窄，或范围树挡住了视线 | 拖动分隔线，或使用标题栏按钮折叠范围树。 |
| 某条结果看起来有误或已过时 | 在依赖它之前，请阅读高亮的源文本并打开 **Full Details**。 |
